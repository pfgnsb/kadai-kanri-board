## 1. 背景と目的

学校の学習課題として、要件を決めてから画面を設計し、そのあと実装する流れを体験するために作る。

自分のやることをカードに書き、リスト（列）で進み具合を見て管理する。Trelloのように、1枚のボードの上でカードを左から右へ移し、同じ列の中でも自由に並べ替えられる使い方にする。

いま動いている本実装は、`frontend/` の React（Vite、`http://localhost:5173`）と、`backend/` の Spring Boot（`http://localhost:8080`）、Docker 上の PostgreSQL である。画面の操作は API 経由で表に残る。`GET /api/health` で接続を確認できる。フォルダ直下の `index.html`、`styles.css`、`app.js` は認識合わせ用のモックであり、本資料の画面と機能は本実装を正とする。

## 3. 機能要件

機能要件とは、「ユーザーがこのアプリでできること」です。

### 3.1 ボード

| No. | できること | 詳細 |
|---|---|---|
| B-1 | ボードを表示する | 起動すると、ボード1枚を表示する。読めないときはエラーを出す |
| B-2 | ボード名を表示する | 左上に見出しとして出す。書き換えない。初期値は「課題管理」 |

### 3.2 リスト

| No. | できること | 詳細 |
|---|---|---|
| L-1 | 初期のリストを出す | API の初期データでは「未着手」「作業中」「完了」の3つ。未着手にカード2枚、作業中に1枚、完了に1枚 |
| L-2 | リストを追加する | 「リストを追加」から名前を入れて作る。最大30文字。空では作れない |
| L-3 | リスト名を表示する | 列の上部に見出しとして出す。書き換えない |
| L-4 | リストを削除する | 削除の前に確認する。中のカードも一緒に消える |

### 3.3 カード

| No. | できること | 詳細 |
|---|---|---|
| C-1 | カードを追加する | タイトルを入れて追加する。優先度の初期値は「中」。説明文と期限は空 |
| C-2 | カードを編集する | カードをクリックして編集画面を開く |
| C-3 | カードを削除する | 編集画面の「削除」で消す。削除の前に確認する |
| C-4 | カードを移動する | カードをつまんで、同じリスト内の好きな位置、または別のリストへ置く |

### 3.4 カードの項目

| 項目 | 必須 / 任意 | 内容 |
|---|---|---|
| タイトル | 必須 | 短い名前。最大80文字。空では保存できない |
| 説明文 | 任意 | くわしいメモ。最大500文字。空でもよい |
| 優先度 | 必須 | 高 / 中 / 低。追加時の初期値は中 |
| 期限 | 任意 | 日付。空でもよい。今日より前の日付は期限切れとして分かりやすく表示する |

### 3.5 保存

| No. | できること | 詳細 |
|---|---|---|
| S-1 | 内容を残す | リストとカードの追加・変更・削除・移動は、Spring Boot の API 経由で PostgreSQL に残す。保存容量を超えたときの専用画面は出さない |
| S-2 | 開き直して復元する | 同じ PostgreSQL なら、開き直しても前回の内容になる。ボードが無いときは「ボードが見つかりません。」と出す |

- **ユースフロー**：やりたいことを達成する道筋
- **操作フロー**：画面上のクリックなどの手順

図は GitHub の Mermaid で書く。部品の詳細は画面設計書を正とする。

### 4.1 全体（課題を1件片づける）

| 項目 | 内容 |
|---|---|
| 種類 | ユースフロー |
| 対応する機能 | B-1、C-1、C-2、C-4、S-1、S-2 |

```mermaid
flowchart TD
  start[課題を1件片づける] --> open[ボードを開く]
  open --> add[未着手にカードを追加する]
  add --> edit[説明・優先度・期限を入れる]
  edit --> work[つまんで作業中へ移す]
  work --> done[つまんで完了へ移す]
```

### 4.2 UF-1 起動する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | B-1、L-1、S-2 |

```mermaid
flowchart TD
  a[Vite の画面を開く] --> b[API からボードを読む]
  b --> c{読めたか}
  c -->|読めた| e[保存してある内容を表示する]
  c -->|ボードが無い| d[見つからない旨を表示する]
  c -->|サーバに繋がらない| n[接続できない旨を表示する]
  e --> f[SCR-01 を表示する]
```

初期データは、リスト「未着手」「作業中」「完了」と、未着手2枚・作業中1枚・完了1枚のカードである。中身の正は `data.sql` とする。

### 4.3 UF-2 カードを追加する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-1、S-1 |

```mermaid
flowchart TD
  a[タスク追加を押す] --> b[タイトルを入力する]
  b --> c{追加かキャンセルか}
  c -->|追加でタイトルあり| d[カードを作る]
  c -->|キャンセル| e[入力をやめる]
  c -->|追加でタイトル空| b
  d --> f[優先度は中、説明と期限は空]
  f --> g[API 経由で残す]
```

### 4.4 UF-3 カードを編集する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-2、C-3、S-1 |

保存・キャンセル・外側クリック・Esc・削除がある。外側クリックと Esc は、保存せずに閉じる。

```mermaid
flowchart TD
  a[カードをクリックする] --> b[SCR-02 が重なる]
  b --> c{次の操作}
  c -->|保存| s1{タイトルはあるか}
  s1 -->|ある| s2[内容を残して閉じる]
  s1 -->|空| s3[エラーを出して開いたまま]
  c -->|キャンセル| x1[保存せず閉じる]
  c -->|外側をクリック、または Esc| x1
  c -->|削除| d1{確認ではいか}
  d1 -->|はい| d2[カードを消して閉じる]
  d1 -->|いいえ| d3[編集画面のまま]
```

### 4.5 UF-4 カードを移動する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-4、S-1 |

カードをつまんで置く操作は画面遷移ではない。同じボード画面の中で、カードの所属リストや並び順を変える。画面の並びは先に変わり、そのあと API へ送る。失敗したときはエラーを出してボードを読み直す。

```mermaid
flowchart TD
  a[カードをつまむ] --> b[同じリスト内の位置、または別リストへ置く]
  b --> c[画面上のその位置へ置く]
  c --> d[API へ移動を送る]
  d --> e{成功したか}
  e -->|成功| f[そのまま]
  e -->|失敗| g[エラーを出し、ボードを読み直す]
```

ドラッグは並びを固定しない。好きな順に置ける。クリックは編集画面を開く操作であり、ドラッグしたあとに誤って開かないようにする。

### 4.6 UF-5 リストを追加・削除する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | L-2、L-4、S-1 |

リスト名の書き換えはしない。

```mermaid
flowchart TD
  start[リストを直す] --> choice{追加か削除か}
  choice -->|追加| a1[+ リストを追加を押す]
  a1 --> a2[列の名前を入れる]
  a2 --> a3{名前があるか}
  a3 -->|ある| a4[追加を押す]
  a4 --> a5[右端にリストができる]
  a3 -->|空| a6[エラーを出して作らない]
  choice -->|削除| d1[削除を押す]
  d1 --> d2{確認ではいか}
  d2 -->|はい| d3[リストと中のカードを消す]
  d2 -->|いいえ| d4[消さない]
```

確認のあと消した内容は元に戻らない。追加と削除は、API が成功してから画面を確定する。ボード名の書き換えはしない。

## 5. 画面要件

画面の部品・最大文字数・色の正は「画面設計書」とする。見た目を先につかむときは「画面見取り図」を見る。この節では画面の役割だけを書く。

| 画面ID | 画面名 | 役割 |
|---|---|---|
| SCR-01 | ボード画面 | 起動後に常に表示する。リストとカードを操作する |
| SCR-02 | カード編集画面 | カードをクリックしたときに重なる。確認・変更・削除をする |

- 上：ボード名の見出しと、「追加や更新はサーバに残ります」
- 中央：リストを横に並べる
- 各リストの上部：リスト名の見出しと、削除
- 各リストの中：カードを上から並べる。つまんで並べ替えできる
- カードをクリックすると、編集画面が重なって開く

画面の行き来は画面設計書の画面遷移図を正とする。カードをつまんで置く操作は画面遷移ではない。

## 6. データと例外

### 6.1 保存と論理モデル

保存は PostgreSQL の boards、lists、cards の3表である。定義の正は `backend/src/main/resources/schema.sql` と「データベース設計」とする。

下の ER は、その3表に対応する。

```mermaid
erDiagram
  boards ||--o{ lists : contains
  lists ||--o{ cards : contains
  boards {
    string id
    string title
    datetime created_at
    datetime updated_at
  }
  lists {
    string id
    string board_id
    string title
    int position
    datetime created_at
    datetime updated_at
  }
  cards {
    string id
    string list_id
    string title
    string description
    string priority
    date due_date
    int position
    datetime created_at
    datetime updated_at
  }
```

- ボード 1 に対してリストは複数
- リスト 1 に対してカードは複数
- `position` は並び順。画面は、この順に並べて出す
- `created_at` と `updated_at` は表の列として持つ

### 6.2 項目の約束

| 対象 | 項目 | 約束 |
|---|---|---|
| ボード | title | 必須。最大40文字。画面からは変えない。初期値は「課題管理」 |
| リスト | title | 必須。最大30文字。画面からは変えない。追加時に空は不可 |
| カード | title | 必須。最大80文字。空では保存できない |
| カード | description | 任意。最大500文字 |
| カード | priority | 必須。high / medium / low。画面では高 / 中 / 低。初期値は medium |
| カード | dueDate | 任意。空でもよい。今日より前なら期限切れ |

API の JSON では期限の名前は `dueDate` である。表の列名は `due_date` である。

### 6.3 例外

| 状況 | 扱い |
|---|---|
| カードのタイトルが空のまま保存する | 「タイトルを入力してください。」を出し、画面は閉じない |
| リスト追加・カード追加で名前が空 | エラーを出し、作らない |
| カードを少し動かさずに離す | 移動せず、クリックとして編集画面を開く |
| カードの移動に失敗する | エラーを出し、ボードを読み直す |
| リスト削除・カード削除を確認してはいで選ぶ | 取り消せない。中のカードもリスト削除と一緒に消える |
| API に繋がらない | 接続を確認する旨を出す |
| ボードが無い | 「ボードが見つかりません。」を出す |
| 別のブラウザで開く | 同じパソコンの同じ API なら、同じ内容になる |
| 別のパソコンで開く | そのパソコンの PostgreSQL の内容になる。自動では同期しない |
| 編集画面の外側をクリックする、または Esc | 保存せずに閉じる |
| 保存容量の超過 | 専用のエラー画面は出さない |

## 8. 非機能要件

数値のミリ秒は定めない。一人が1枚のボードを手元で使う前提で、保証することと今回しないことを分ける。

### 8.1 動作環境

| 今回保証する | 今回しない |
|---|---|
| Windows のパソコンで、Chrome または Edge を使う | Safari や Firefox での動作保証 |
| 画面は `http://localhost:5173`、API は `http://localhost:8080` | スマートフォン専用アプリ、インストール必須の配布 |

### 8.2 速さ（体感）

| 今回保証する | 今回しない |
|---|---|
| 手元の枚数なら、操作のあと画面が止まらず更新される | 応答時間のミリ秒、負荷試験、大量カードの保証 |

### 8.3 オフラインと可用性

| 今回保証する | 今回しない |
|---|---|
| 手元で API と PostgreSQL が動いていれば、インターネットがなくても使える | サーバの稼働率、24時間運用、障害窓口。API を止めた状態での操作 |

### 8.4 データの残り方

| 今回保証する | 今回しない |
|---|---|
| 同じパソコンの PostgreSQL に残る。開き直しても同じデータベースなら内容が残る | バックアップ、別パソコンへの同期、無期限保管 |
| データベースを消すと内容も消える | 容量超過の専用画面 |

### 8.5 セキュリティ

| 今回保証する | 今回しない |
|---|---|
| ログインはない。画面に出す文字は React の表示でエスケープする。API は手元の localhost だけ | 認証、通信の暗号化、他の人が同じパソコンを使ったときの保護 |

### 8.6 運用ログ

運用ログ、監視、障害対応の記録は作らない。学習課題の提出用アプリであるため。

## 9. 技術の選定

使う技術の正は「技術スタック」とする。要約だけここに置く。

画面は React（Vite）。サーバは Spring Boot（Java 21）。保存は手元の PostgreSQL。画面は JavaScript、API は Java。Next.js は今回の対象外である。

| 採用するもの | 理由 |
|---|---|
| React（Vite） | 画面をコンポーネントで組む。Next.js は使わない |
| Spring Boot（Java 21） | JSON の REST API を書く。ボードの読み書き、リストとカードの追加・更新・削除・移動を行う |
| PostgreSQL + JDBC | 指定の RDB。SQL が見える。Docker Compose で起動する |
| Chrome または Edge | 提出と説明で使うブラウザ |

| 採用しないもの | 理由 |
|---|---|
| Next.js | 今回の指定で対象外 |
| Node.js + Express（API） | API は Spring Boot に切り替えた |
| TypeScript / ORM / 状態ライブラリ | 今回の範囲では JDBC と React の state で足りる |
| クラウド上のデータベース | 手元の PostgreSQL で足りる |
| ドラッグ用のライブラリ | 使わない。標準のポインタ操作で、つかんで並べ替える |

## 11. 完成の定義

確認する人は利用者の nsb。環境は手元の PostgreSQL と Spring Boot、React（Vite）を起動し、Chrome または Edge で画面を開くこと。開き方の正は「操作手順書」と「技術スタック」とする。

次をすべて満たせば、最初の完成とする。

1. 初期データではリストが3つある
2. カードを追加・編集・削除できる
3. カードにタイトル・説明文・優先度を付けられる
4. 期限は入れることも、空にすることもできる
5. カードをつまんで、同じリスト内の位置または別のリストへ移せる
6. リストを追加・削除できる。ボード名とリスト名は書き換えない
7. ページを開き直しても内容が消えない（同じパソコンの PostgreSQL）

対象外の機能が無いことは、不合格にしない。
