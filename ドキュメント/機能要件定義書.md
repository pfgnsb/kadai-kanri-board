## 1. システムの目的（機能面）

自分のやることをカードに書き、リスト（列）で進み具合を見て管理する。  
Trelloのように、1枚のボードの上でカードを左から右へ移していく。

| 項目 | 内容 |
|---|---|
| 対象 | 一人が、手元のブラウザで、課題をカードとして管理すること |
| 中心の操作 | カードの追加・編集・削除・左右移動、リストの追加・改名・削除、ボード名の変更 |
| 保存 | 操作のたびに同じブラウザへ自動で残す |

---

## 2. 利用者と利用の前提

| 項目 | 内容 |
|---|---|
| 利用者 | nsb 一人。ログインはない |
| 画面 | メインはボード画面（SCR-01）1枚。カード編集時だけ重ねて開く（SCR-02） |
| 動かす場所 | 自分のパソコンの Chrome または Edge。`index.html` を直接開く |
| ネットワーク | 不要。オフラインで使える |
| 共有 | 他の人との同時利用・招待はない |

## 3. 機能の範囲

### 3.1 今回作る機能（概要）

| 分類 | できること |
|---|---|
| ボード | 起動時に1枚表示する。名前を変更する |
| リスト | 初期3列を出す。追加・改名・削除する |
| カード | 追加・編集・削除する。隣のリストへ左右に移す |
| カードの項目 | タイトル（必須）、説明文、優先度、期限 |
| 保存 | 本実装は API 経由で PostgreSQL に残す。モックは localStorage |

詳細な番号（B-1、L-1、C-1、S-1 など）は「機能要件」を正とする。

### 3.2 今回作らない機能

次は機能の対象外とする。必要になったら要件定義書を改訂してから追加する。

- ログイン、会員登録
- 複数人での共有、招待、権限
- 複数ボード
- カードをつかんで移す操作（ドラッグ）
- コメント、チェックリスト、ファイル添付
- 通知、メール
- スマートフォン専用アプリ
- 別のパソコンへの自動同期
- SQLite、クラウド保存
- 保存容量超過の専用画面
- 運用ログ、監視

## 4. 機能分類と画面の対応

| 分類 | 主な操作 | 画面 |
|---|---|---|
| ボード | 表示、名前変更 | SCR-01 |
| リスト | 追加、改名、削除 | SCR-01 |
| カード | 追加、左右移動 | SCR-01 |
| カード | 編集、削除 | SCR-02（SCR-01 の上に重なる） |
| 保存 | 自動保存、復元 | 画面操作に付随する。専用画面は無い |

「左へ」「右へ」は画面遷移ではない。同じボード画面の中で、隣のリストの一番下へ移す。

## 5. 機能ごとの定義

### 5.1 ボード

起動するとボード1枚だけを出す。左上の名前を書き換えて欄の外をクリックすると、ボード名が変わる。空にした場合は「課題管理」に戻す。最大40文字。

### 5.2 リスト

初めて開いたときは「未着手」「作業中」「完了」の3つを出す。  
「リストを追加」から名前を入れて右端に作る。列の上部の名前は書き換えられる。空にすると元の名前に戻す。削除の前に確認し、中のカードも一緒に消える。リスト名は最大30文字。

### 5.3 カード

タイトルを入れて追加する。優先度の初期値は「中」。説明文と期限は空。  
カードをクリックすると編集画面が開き、タイトル・説明文・優先度・期限を直せる。削除は編集画面から行い、確認のあと消す。  
「左へ」「右へ」で隣のリストの一番下へ移す。端のリストでは、それ以上進めないボタンは押せない。

### 5.4 カードの項目

| 項目 | 必須 / 任意 | 約束 |
|---|---|---|
| タイトル | 必須 | 最大80文字。空では保存できない |
| 説明文 | 任意 | 最大500文字。空でもよい |
| 優先度 | 必須 | 高 / 中 / 低。追加時の初期値は中 |
| 期限 | 任意 | 日付。空でもよい。今日より前なら期限切れとして分かりやすく表示する |

### 5.5 保存

リストとカードの追加・変更・削除・移動は、本実装では Spring Boot の API 経由で PostgreSQL に残す。PostgreSQL は Docker Compose で起動し、接続設定は入っている。リストとカードの追加、カードの更新、左右移動の API はある。削除の API はこれからである。  
モックは localStorage（キー `task-board-v1`）に残す。ページを閉じても、同じブラウザで開くと前回の内容を表示する。保存がない、または JSON が壊れているときは初期ボードを出す。  
保存容量を超えたときの専用画面は出さない。

## 6. ユースフローと操作フロー

- **ユースフロー**：やりたいことを達成する道筋
- **操作フロー**：画面上のクリックなどの手順

図の部品の詳細は画面設計書を正とする。機能番号の正は「機能要件」とする。

### 6.1 全体（課題を1件片づける）

| 項目 | 内容 |
|---|---|
| 種類 | ユースフロー |
| 対応する機能 | B-1、C-1、C-2、C-4、S-1、S-2 |

```mermaid
flowchart TD
  start[課題を1件片づける] --> open[ボードを開く]
  open --> add[未着手にカードを追加する]
  add --> edit[説明・優先度・期限を入れる]
  edit --> work[右へで作業中へ移す]
  work --> done[右へで完了へ移す]
```

### 6.2 UF-1 起動する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | B-1、L-1、S-2 |

```mermaid
flowchart TD
  a[index.html を開く] --> b[loadBoard する]
  b --> c{保存データはあるか}
  c -->|ない、または JSON が使えない| d[初期ボードを出す]
  c -->|ある| e[前回の内容を復元する]
  d --> f[SCR-01 を表示する]
  e --> f
```

初期ボードは、リスト「未着手」「作業中」「完了」と、未着手の説明用カード1枚である。

### 6.3 UF-2 カードを追加する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-1、S-1 |

```mermaid
flowchart TD
  a[タスク追加を押す] --> b[タイトルを入力する]
  b --> c{追加かキャンセルか}
  c -->|追加でタイトルあり| d[カードを作る]
  c -->|キャンセル| e[入力をやめる]
  c -->|追加でタイトル空| b
  d --> f[優先度は中、説明と期限は空]
  f --> g[自動保存する]
```

### 6.4 UF-3 カードを編集する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-2、C-3、S-1 |

保存・キャンセル・外側クリック・削除の4通りがある。

```mermaid
flowchart TD
  a[カードをクリックする] --> b[SCR-02 が重なる]
  b --> c{次の操作}
  c -->|保存| s1{タイトルはあるか}
  s1 -->|ある| s2[内容を残して閉じる]
  s1 -->|空| s3[エラーを出して開いたまま]
  c -->|キャンセル| x1[保存せず閉じる]
  c -->|外側をクリック| x1
  c -->|削除| d1{確認ではいか}
  d1 -->|はい| d2[カードを消して閉じる]
  d1 -->|いいえ| d3[編集画面のまま]
```

### 6.5 UF-4 カードを移動する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | C-4、S-1 |

```mermaid
flowchart TD
  a[左へまたは右へを押す] --> b{その方向に隣のリストはあるか}
  b -->|ない端のリスト| c[ボタンは押せない]
  b -->|ある| d[隣のリストの一番下へ移す]
  d --> e[自動保存する]
```

### 6.6 UF-5 リストを追加・改名・削除する

| 項目 | 内容 |
|---|---|
| 種類 | 操作フロー |
| 対応する機能 | L-2、L-3、L-4、S-1 |

```mermaid
flowchart TD
  start[リストを直す] --> choice{追加・改名・削除のどれか}
  choice -->|追加| a1[+ リストを追加を押す]
  a1 --> a2[列の名前を入れる]
  a2 --> a3[追加を押す]
  a3 --> a4[右端にリストができる]
  choice -->|改名| r1[列の上部の名前を書き換える]
  r1 --> r2{空か}
  r2 -->|空| r3[元の名前に戻す]
  r2 -->|あり| r4[新しい名前を残す]
  choice -->|削除| d1[削除を押す]
  d1 --> d2{確認ではいか}
  d2 -->|はい| d3[リストと中のカードを消す]
  d2 -->|いいえ| d4[消さない]
```

確認のあと消した内容は元に戻らない。

```mermaid
  b --> c{空か}
  c -->|空| d[課題管理に戻す]
  c -->|あり| e[新しい名前にする]

```

## 7. 完成の定義

確認する人は利用者の nsb。環境は Chrome または Edge で `index.html` を直接開くこと。

次をすべて満たせば、機能面の最初の完成とする。

1. 画面を開くとリストが3つある
2. カードを追加・編集・削除できる
3. カードにタイトル・説明文・優先度を付けられる
4. 期限は入れることも、空にすることもできる
5. カードを左右のリストへ移せる
6. リストを追加・名前変更・削除できる
7. ページを開き直しても内容が消えない（同じパソコンの同じブラウザ）

対象外の機能が無いことは、不合格にしない。

## 8. 資料の使い分け

| 資料 | この資料との違い |
|---|---|
| 要件定義書 | 背景・非機能・対象外を含む全体の約束。本資料より広い |
| 機能要件 | 機能を番号付きの一覧にした確認用の表。本資料の詳細の正 |
| 画面設計書 | 部品の配置と動きの正 |
| ER図・データベース設計 | データの形。機能の中身そのものではない |
| 技術スタック | 使う技術の選定。機能の中身そのものではない |

機能の範囲を変えるときは、先に要件定義書と本資料を直し、機能要件の番号表も直す。
