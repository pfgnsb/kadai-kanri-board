# ドキュメント一覧

| 3 | [機能要件定義書.md](./機能要件定義書.md) | 機能の範囲・流れ・完成の定義 |
| 4 | [機能要件.md](./機能要件.md) | できることを番号付きの一覧にする |

用語定義書で言葉を固定し、要件定義書で全体を決めます。機能の詳細は機能要件定義書と機能要件、データの形は ER図とデータベース設計、使う技術は技術スタックです。画面設計書で見た目を決めます。画面見取り図は、画面設計書を読むときのイメージです。HTMLモックアップ作成計画は、既存の `index.html` を認識合わせ用モックとする約束です。操作手順書は、完成したアプリの使い方です。

要件定義書 2.0 では、背景と目的、利用者、ユースフローと操作フロー、データと例外、データの流れ、非機能要件、技術の選定、資料の役割を足しています。画面設計書には画面遷移を足しています。2026年9月20日に、機能・データ・技術の部分を独立資料に分けました。同日、HTMLモックアップ作成計画を追加しました。要件定義書本体はそのまま残しています。

図はすべて GitHub 向けの Mermaid です。コードブロックの言語名を mermaid にし、フロー図は `flowchart`、データの関係は `erDiagram` で書いています。GitHub で Markdown を開くと図として見られます。
