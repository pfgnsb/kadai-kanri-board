# ドキュメント一覧

プログラムより先に決める資料です。読む順番は次のとおりです。

| 順番 | 資料 | 役割 |
|---|---|---|
| 1 | [用語定義書.md](./用語定義書.md) | 使う言葉の意味を揃える辞書 |
| 2 | [要件定義書.md](./要件定義書.md) | 何を作るか、何を作らないかを決める |
| 3 | [画面設計書.md](./画面設計書.md) | 画面の配置と、各ボタンの役割 |
| 4 | [画面見取り図.md](./画面見取り図.md) | 画面の見た目をつかむ補助 |
| 5 | [操作手順書.md](./操作手順書.md) | 開き方と、基本の使い方 |

用語定義書で言葉を固定し、要件定義書で機能を決め、画面設計書で見た目を決めます。画面見取り図は、画面設計書を読むときのイメージです。操作手順書は、完成したアプリの使い方です。

要件定義書 2.0 では、背景と目的、利用者、ユースフローと操作フロー、データと例外、データの流れ、非機能要件、技術の選定、資料の役割を足しています。画面設計書には画面遷移を足しています。

図はすべて GitHub 向けの Mermaid です。コードブロックの言語名を mermaid にし、フロー図は `flowchart`、データの関係は `erDiagram` で書いています。GitHub で Markdown を開くと図として見られます。
