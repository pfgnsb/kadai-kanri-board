## 1. 画面（React / Vite）

| 用語 | 意味 | このアプリでは |
|---|---|---|
| SPA | 画面を1枚のアプリとしてブラウザで動かし、ページ全体を読み直さずに中身を切り替える形 | ボード画面と、その上に重なるカード編集 |
| React | 画面を部品に分けて組み立てるライブラリ | `frontend/`。関数コンポーネントで書く |
| JSX | JavaScript の中に、HTML に似たタグを書く書き方 | 画面の部品の記述 |
| コンポーネント | 画面の部品。組み合わせて1枚の画面にする | ボード、リスト、カード、編集画面 |
| Hooks | 関数コンポーネントに、状態や表示後の処理を足す仕組み | `useState`（今の値）、`useEffect`（表示後の処理） |
| state | 画面が覚えている今の値。変わると表示が更新される | API から取ったボードのデータ |
| Vite | React の開発サーバと、本番用ファイルを作る道具 | 開発は `http://localhost:5173`。本番用は `npm run build` |
| npm | JavaScript のパッケージを入れる道具 | `frontend/` で使う |
| ビルド | ソースから、ブラウザに置くファイルを作ること | 結果は `frontend/dist` |
| fetch | ブラウザ標準で API を呼ぶ関数 | 画面から `/api` を呼ぶ |
| CORS | 別のポートの画面から API を呼ぶことを、サーバが許可する仕組み | 開発中、5173 から 8080 を呼ぶために許可している |

## 2. API（Spring Boot / Java）

| 用語 | 意味 | このアプリでは |
|---|---|---|
| API | 画面がサーバに頼む窓口 | `/api/health` や `/api/board` など |
| REST | URL と HTTP の種類で操作を表す呼び方 | 読み取りは GET、追加は POST、更新は PUT、削除は DELETE |
| JSON | データの文字の形。`{ "status": "ok" }` のような書き方 | API の要求と応答 |
| Spring Boot | Java で API サーバを作る枠組み | `backend/`。ポートは 8080 |
| JDK | Java のプログラムを動かすための一式 | 21。EC2 では Amazon Corretto |
| Maven | Java のビルドと、依存する部品の管理 | PC に入れず、`mvnw.cmd`（Wrapper）で使う |
| jar | Java のプログラムを1つにまとめたファイル | EC2 では `/opt/task-board/task-board.jar` |
| JDBC | Java からデータベースへ SQL を送る仕組み | Spring Boot から PostgreSQL へつなぐ |
| エンドポイント | API の1つの URL | 例: `GET /api/health` |
| ヘルスチェック | サーバとデータベースが生きているかの確認 | `{"status":"ok","database":"up"}` が返ればよい |

## 3. 保存（PostgreSQL / Docker）

| 用語 | 意味 | このアプリでは |
|---|---|---|
| DBMS | データベースを管理するソフト | PostgreSQL 16 |
| テーブル | データを行と列で置く表 | `boards` / `lists` / `cards` |
| SQL | 表を読み書きする言語 | `schema.sql` に書く |
| UUID | 衝突しにくい識別子 | ボード、リスト、カードの ID |
| Docker | 必要なソフトを、コンテナという箱で動かす仕組み | 手元の PostgreSQL 用 |
| Docker Compose | コンテナの起動内容をファイルに書く道具 | 手元用。`docker-compose.yml` |
| イメージ | コンテナのひな形 | `postgres:16-alpine` |
| localStorage | ブラウザがパソコン内に文字を残す場所 | フォルダ直下のモックが使う。本実装の保存は PostgreSQL |

## 4. AWS（載せる場所）

| 用語 | 意味 | このアプリでは |
|---|---|---|
| リージョン | AWS の地域 | 東京 `ap-northeast-1` |
| VPC | 自分用のネットワークの区画 | 既定の VPC を使う |
| サブネット | VPC の中をさらに分けた区画 | 既定のサブネットに EC2 を置く |
| アベイラビリティゾーン | リージョンの中の拠点 | インスタンスを置いた場所。`terraform output` で見られる |
| EC2 | 借りる仮想サーバ | 1台。画面と API を同じマシンに置く |
| インスタンス | 起動しているその1台 | 型は `t4g.small` |
| AMI | インスタンスの OS のひな形 | Amazon Linux 2023（arm64） |
| 公開アドレス | 外から届く IP | `terraform output public_ip`。停止して起動し直すと変わる |
| RDS | AWS が面倒を見るデータベース | PostgreSQL 16。EC2 からだけ接続する |
| エンドポイント（RDS） | RDS のホスト名 | 公開アドレスはない。VPC の中の名前 |
| セキュリティグループ | どの通信を通すかのルール | 22 / 80 / 5173 / 8080 はこの PC だけ。5432 は EC2 だけ |
| ingress | 外から中へ入る通信 | 上のポート |
| egress | 中から外へ出る通信 | SSM のために残してある |
| CIDR | アドレスの範囲の書き方 | `このPCのアドレス/32` は、その1台だけ |
| SSH | サーバに文字で入る接続 | ユーザーは `ec2-user`。秘密鍵は `infra/keys/task-board` |
| 鍵ペア | 公開鍵と秘密鍵の組 | 公開鍵は AWS に登録し、秘密鍵はこの PC に置く |
| IAM ロール | AWS の中で、そのサーバに許す操作 | EC2 に付け、SSM 用の権限を持たせる |
| SSM | サーバを AWS 経由で扱う仕組み | 外へ出る通信を残す理由 |
| gp3 | ディスクの種類 | EC2 の起動ディスク。RDS も gp3 |
| nginx | 入口の Web サーバ | 80 番。画面のファイルを返し、`/api` は中の 8080 へ渡す |
| リバースプロキシ | 受け取った通信を、奥のサーバへ渡すこと | `location /api/` の `proxy_pass` |
| systemd | Linux でサービスを起動し、落ちたら上げ直す仕組み | `task-board.service`。`Restart=on-failure` |

## 5. Terraform（土台の定義）

| 用語 | 意味 | このアプリでは |
|---|---|---|
| Terraform | サーバやデータベースを、コードの定義どおりに作る道具 | 定義は `infra/` |
| リソース | 作るものの1つ | EC2、RDS、セキュリティグループ、鍵など |
| `terraform init` | 使う部品を取得し、作業の準備をする | `infra` で最初に実行する |
| `terraform apply` | 定義どおりに AWS へ作る、または直す | EC2 と RDS ができる。RDS は 10 分近くかかることがある |
| `terraform destroy` | 定義で作ったものを消す | EC2 のディスクも消える。RDS の最終スナップショットは残さない |
| `terraform output` | 作ったあとに知りたい値を出す | `public_ip` と `db_endpoint` |
| variable | 定義の外から渡す値 | パスワードと、この PC のアドレス |
| tfvars | variable の実値を置くファイル | `infra/terraform.tfvars`。Git には入れない |
| tfstate | いま AWS に何があるかを Terraform が覚えているファイル | Git には入れない |
| sensitive | 出力やログに出しにくくする印 | `db_password` |
